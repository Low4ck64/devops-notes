## HEAD

**HEAD** — указатель на текущее место в истории Git, то есть "где я сейчас". Обычно указывает на последний коммит текущей ветки. Сам по себе HEAD не команда и ничего не делает.

При переключении ветки (`git switch имя`) HEAD перемещается на неё, а при новом коммите сдвигается вместе с веткой.

### Обозначения коммитов относительно HEAD

- `HEAD~1` — предыдущий коммит (родитель текущего)
- `HEAD~2` — на два коммита назад
- `HEAD~3` — на три коммита назад

`HEAD~3` сама никуда не переходит, это просто обозначение коммита. Его подставляют в другие команды.

### Команды с HEAD

```bash
git show HEAD~3                       # посмотреть, что изменилось в том коммите
git show HEAD~3:файл.md               # посмотреть файл в том состоянии
git diff HEAD~3                       # сравнить текущее состояние с тем коммитом
git restore --source=HEAD~3 файл.md   # вернуть старую версию файла в папку
git switch --detach HEAD~3            # перейти на тот коммит (detached HEAD)
git switch main                       # вернуться обратно на ветку
```

### Detached HEAD

Состояние, когда HEAD указывает не на ветку, а прямо на коммит (например, после перехода на старый коммит). Новые коммиты там не принадлежат ни одной ветке и могут потеряться.

Чтобы работать от старого коммита, сначала создай ветку:

```bash
git switch -c новая-ветка HEAD~3
```

### Зачем переходить на старые коммиты

- посмотреть, как выглядел файл или проект раньше
- найти коммит, в котором появилась ошибка (`git bisect`)
- начать новую ветку от старого места

- HEAD^ обозначает родителя текущего коммита в истории текущей ветки; сам по себе ничего не перемещает, перемещение выполняют команды (git switch --detach, git reset), в которые он подставлен.


## Отмена изменений: reset и revert

### git reset

Откатывает текущую ветку (вместе с HEAD) на указанный коммит. Коммиты после этого места из ветки «отваливаются», то есть история переписывается.

```bash
git reset HEAD~1    # откатиться на один коммит назад
```

#### Режимы

| Режим | Коммиты | Индекс (после `git add`) | Файлы в папке |
|---|---|---|---|
| `--soft` | откатывает | изменения остаются добавленными | не трогает |
| `--mixed` (по умолчанию) | откатывает | сбрасывает (нужен новый `git add`) | не трогает |
| `--hard` | откатывает | сбрасывает | возвращает к старому состоянию, изменения удаляются |

```bash
git reset --soft HEAD~1    # отменить коммит, изменения готовы к новому коммиту
git reset HEAD~1           # отменить коммит, изменения остались в файлах
git reset --hard HEAD~1    # отменить коммит и стереть изменения
```

#### Убрать файл из `git add`

Если добавил файл по ошибке и коммит ещё не делал:

```bash
git reset файл.md
```

Содержимое файла не меняется, он просто перестаёт быть «готовым к коммиту».

#### Осторожно

- `--hard` удаляет незакоммиченные изменения без возможности вернуть их. Перед ним проверь `git status`.
- Не делай `reset` для коммитов, которые уже отправлены на GitHub и которыми пользуются другие: история разойдётся.
- Если откатил лишнее, коммиты можно найти через `git reflog` (он показывает, где был HEAD) и вернуть.

### git revert

Создаёт **новый коммит с обратными изменениями**, который отменяет указанный коммит. Старый коммит остаётся в истории, она не переписывается.

```bash
git revert HEAD        # отменить последний коммит
git revert a1b2c3d     # отменить конкретный коммит по идентификатору
```

История после revert:

```
A --- B --- C --- C'
```

`C'` это revert-коммит, который отменяет изменения `C`. Файлы выглядят так, будто `C` не было, но сам `C` остаётся в истории.

### Сравнение

| | `git reset` | `git revert` |
|---|---|---|
| Что делает | двигает ветку назад | добавляет новый коммит-отмену |
| История | переписывается | сохраняется |
| Для опубликованных коммитов | опасен | безопасен |
| Когда использовать | локальные, ещё не отправленные коммиты | коммиты, уже отправленные на GitHub |


-git cherry-pick <коммит> копирует выбранный коммит в текущую ветку, создавая новый коммит с теми же изменениями.

-git rebase -i HEAD~N открывает список последних N коммитов, где можно объединять (squash, fixup), переименовывать (reword), удалять (drop) и переставлять коммиты. Переписывает историю, поэтому применять только к ещё не опубликованным коммитам.

### git clone 

Скачивает репозиторий целиком. Делается один раз на проект: создаёт папку, историю и запоминает адрес GitHub под именем `origin`

### git fetch

Скачивает новые коммиты с GitHub в `origin/main`, но **не меняет** твою ветку и файлы. Безопасная команда.

```bash
git fetch
git log --oneline main..origin/main    # посмотреть, что пришло нового
git merge origin/main                  # влить новое в свою ветку

### git pull

Делает `fetch` и сразу `merge` в текущую ветку.

```bash
git pull
```

`git pull` = `git fetch` + `git merge`.

| | `git fetch` | `git pull` |
|---|---|---|
| Скачивает новые коммиты | да | да |
| Меняет твою ветку и файлы | нет | да |
| Безопасность | безопасен | может вызвать merge conflict |

## Сравнение изменений: git diff

Показывает, чем отличаются три места: рабочая папка, индекс (после `git add`) и последний коммит (`HEAD`).

| Команда | Что сравнивает |
|---|---|
| `git diff` | рабочая папка и индекс (правки, ещё не добавленные) |
| `git diff --staged` | индекс и последний коммит (то, что попадёт в коммит) |
| `git diff HEAD` | рабочая папка и последний коммит (все правки) |

В выводе строка с `-` — удалено, строка с `+` — добавлено.

Хорошая привычка: перед коммитом проверять `git diff --staged`.

## История коммитов: git log

Показывает цепочку коммитов от новых к старым. Каждый коммит ссылается на предыдущий (родителя).

```bash
git log                           # полный вид: автор, дата, сообщение
git log --oneline                 # по одной строке на коммит
git log --oneline -3              # три последних коммита
git log --oneline --graph --all   # граф всех веток
git log -p файл.md                # история одного файла вместе с правками
```

Пример вывода `git log --oneline`:

```
e0f1a2 (HEAD -> main) добавил revert
7b8c9d добавил reset
d4e5f6 добавил ветки
a1b2c3 первый коммит
```

`HEAD -> main` показывает, что ты на ветке `main` и это её последний коммит.

## Права доступа: rwx, chmod, sudo

Как прочитать права командой ls -l
этот шаг ~2 мин

Команду ls -l вы уже видели. Первая колонка в ее выводе, на которую мы пока не смотрели, и есть права:

-rwxr-xr--  1  deploy  devops  812  config.sh

Левый блок -rwxr-xr-- кодирует все права на файл. Читается он так:
Первый символ – тип, про него мы говорили: дефис для обычного файла, d для директории. Дальше идут три одинаковые тройки rwx, и каждая буква на своем месте:

    r (read) – читать содержимое;
    w (write) – изменять и удалять;
    x (execute) – запускать файл как программу.

Если права нет, на его месте стоит дефис. Тройки идут для трех категорий: первая для владельца файла, вторая для его группы, третья для всех остальных. У каждого файла есть владелец (пользователь, обычно тот, кто его создал) и группа, и в выводе выше это deploy и devops. Так система и решает, что вам можно: смотрит, кто вы по отношению к файлу, и берет соответствующую тройку.

У директорий буквы значат почти то же, но с поправкой: x на директории – это право зайти в нее (cd) и обращаться к файлам внутри, а r – право посмотреть список ее содержимого.

## меняем права командой chmod

Менять права умеет команда chmod (change mode). У нее есть понятная буквенная запись: кому что добавить или убрать.

chmod +x deploy.sh        # разрешить запуск (всем категориям)
chmod u+w notes.txt       # владельцу (user) добавить запись
chmod go-r secret.txt     # группе и остальным убрать чтение

Здесь u – владелец (user), g – группа, o – остальные (others), a – все сразу. Знак + добавляет право, - убирает.

## Числовая запись прав

Те же права часто записывают числом, и в чужих инструкциях вы постоянно будете видеть chmod 755 или chmod 644. Расшифровывается это просто. Каждой букве дано значение: r – 4, w – 2, x – 1. Права одной категории складывают, и получается цифра от 0 до 7. Три категории дают три цифры.

## Числовая запись прав

Значения букв: `r = 4`, `w = 2`, `x = 1` (складываются).

| Число | Владелец / группа / остальные | Смысл |
|:-----:|:-----------------------------:|-------|
| `644` | `rw-` `r--` `r--` | Обычный файл: владелец правит, прочие читают |
| `755` | `rwx` `r-x` `r-x` | Скрипт, директория: прочие читают и запускают |
| `600` | `rw-` `---` `---` | Секрет, только владелец: ставят на приватный SSH-ключ |

Последняя строка особенно важна, потому что именно 600 нужно ставить на приватный SSH-ключ из прошлого шага. Если права на него слишком открыты и его может прочитать кто-то еще, SSH откажется его использовать и просто не пустит вас на сервер. Так система заставляет держать секреты закрытыми.

## Смена владельца командой chown

Если chmod меняет, что можно делать, то chown (change owner) меняет, чей это файл. Пригождается, когда файл создан одним пользователем, а работать с ним должен другой или вообще служба:

sudo chown deploy:devops config.yaml   # владелец deploy, группа devops

Слева от двоеточия новый владелец, справа группа. Команда меняет принадлежность файла, поэтому почти всегда требует прав администратора, к которым мы сейчас и переходим.

## root и sudo

Над всеми правами стоит особый пользователь root, администратор системы. Для него ограничения rwx не действуют: root может читать, менять и удалять что угодно. Поэтому установка программ, управление службами и правка системных файлов делаются именно от него.

Сидеть под root постоянно не нужно и опасно (об этом ниже), поэтому обычный пользователь повышает права точечно, командой sudo, что означает «выполнить вот это одно действие от имени root».

sudo apt install nginx
sudo systemctl restart nginx


Все, что меняет систему, идет через sudo, а осмотр и работа со своими файлами без него.

## Термины прав доступа

| Термин | Что означает |
|--------|--------------|
| Права доступа | Кто может читать, изменять и запускать файл |
| `r`, `w`, `x` | Чтение, запись, выполнение |
| Владелец / группа / остальные | Три категории, для которых заданы права |
| `chmod` | Меняет права на файл |
| Числовая запись | Права как три цифры: r=4, w=2, x=1, складываются по категориям |
| `chown` | Меняет владельца и группу файла |
| `root` | Администратор системы, для которого ограничения прав не действуют |
| `sudo` | Выполнить одну команду от имени root |
