## HEAD

**HEAD** — указатель на текущее место в истории Git, то есть "где я сейчас". Обычно указывает на последний коммит текущей ветки. Сам по себе HEAD не команда и ничего не делает.

При переключении ветки (`git switch имя`) HEAD перемещается на неё, а при новом коммите сдвигается вместе с веткой.

### Обозначения коммитов относительно HEAD

- `HEAD~1` — предыдущий коммит (родитель текущего)
- `HEAD~2` — на два коммита назад
- `HEAD~3` — на три коммита назад

`HEAD~3` сама никуда не переходит, это просто обозначение коммита. Его подставляют в другие команды.

### Команды с HEAD

```bash
git show HEAD~3                       # посмотреть, что изменилось в том коммите
git show HEAD~3:файл.md               # посмотреть файл в том состоянии
git diff HEAD~3                       # сравнить текущее состояние с тем коммитом
git restore --source=HEAD~3 файл.md   # вернуть старую версию файла в папку
git switch --detach HEAD~3            # перейти на тот коммит (detached HEAD)
git switch main                       # вернуться обратно на ветку
```

### Detached HEAD

Состояние, когда HEAD указывает не на ветку, а прямо на коммит (например, после перехода на старый коммит). Новые коммиты там не принадлежат ни одной ветке и могут потеряться.

Чтобы работать от старого коммита, сначала создай ветку:

```bash
git switch -c новая-ветка HEAD~3
```

### Зачем переходить на старые коммиты

- посмотреть, как выглядел файл или проект раньше
- найти коммит, в котором появилась ошибка (`git bisect`)
- начать новую ветку от старого места

- HEAD^ обозначает родителя текущего коммита в истории текущей ветки; сам по себе ничего не перемещает, перемещение выполняют команды (git switch --detach, git reset), в которые он подставлен.


## Отмена изменений: reset и revert

### git reset

Откатывает текущую ветку (вместе с HEAD) на указанный коммит. Коммиты после этого места из ветки «отваливаются», то есть история переписывается.

```bash
git reset HEAD~1    # откатиться на один коммит назад
```

#### Режимы

| Режим | Коммиты | Индекс (после `git add`) | Файлы в папке |
|---|---|---|---|
| `--soft` | откатывает | изменения остаются добавленными | не трогает |
| `--mixed` (по умолчанию) | откатывает | сбрасывает (нужен новый `git add`) | не трогает |
| `--hard` | откатывает | сбрасывает | возвращает к старому состоянию, изменения удаляются |

```bash
git reset --soft HEAD~1    # отменить коммит, изменения готовы к новому коммиту
git reset HEAD~1           # отменить коммит, изменения остались в файлах
git reset --hard HEAD~1    # отменить коммит и стереть изменения
```

#### Убрать файл из `git add`

Если добавил файл по ошибке и коммит ещё не делал:

```bash
git reset файл.md
```

Содержимое файла не меняется, он просто перестаёт быть «готовым к коммиту».

#### Осторожно

- `--hard` удаляет незакоммиченные изменения без возможности вернуть их. Перед ним проверь `git status`.
- Не делай `reset` для коммитов, которые уже отправлены на GitHub и которыми пользуются другие: история разойдётся.
- Если откатил лишнее, коммиты можно найти через `git reflog` (он показывает, где был HEAD) и вернуть.

### git revert

Создаёт **новый коммит с обратными изменениями**, который отменяет указанный коммит. Старый коммит остаётся в истории, она не переписывается.

```bash
git revert HEAD        # отменить последний коммит
git revert a1b2c3d     # отменить конкретный коммит по идентификатору
```

История после revert:

```
A --- B --- C --- C'
```

`C'` это revert-коммит, который отменяет изменения `C`. Файлы выглядят так, будто `C` не было, но сам `C` остаётся в истории.

### Сравнение

| | `git reset` | `git revert` |
|---|---|---|
| Что делает | двигает ветку назад | добавляет новый коммит-отмену |
| История | переписывается | сохраняется |
| Для опубликованных коммитов | опасен | безопасен |
| Когда использовать | локальные, ещё не отправленные коммиты | коммиты, уже отправленные на GitHub |


-git cherry-pick <коммит> копирует выбранный коммит в текущую ветку, создавая новый коммит с теми же изменениями.

-git rebase -i HEAD~N открывает список последних N коммитов, где можно объединять (squash, fixup), переименовывать (reword), удалять (drop) и переставлять коммиты. Переписывает историю, поэтому применять только к ещё не опубликованным коммитам.
